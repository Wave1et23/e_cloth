## 3. 每页交互说明

通用约定：

- 所有页面移动端优先，窄屏不横向溢出；不加阴影，用 `--line` 细边框与留白分层。
- 数据页三态：**加载中 / 空数据 / 加载失败**；失败一律给「重试」。
- 破坏性操作二次确认；错误文案中文人话，不出现堆栈、SQL、英文错误码。
- 标题用宋体栈 `--font-display`，正文用系统无衬线 `--font-body`；不引入 webfont。
- 提交流程：按钮进入 loading 并禁用，防止连点；成功后明确反馈。

### 3.1 `/` 首页

**游客态（未登录）**

- 首屏：品牌名「衣橱镜像」+ 一句主张「给现实衣柜建一份数字档案，扫一下就记下今天穿了什么」。
- 三个步骤条：`拍照建档 → 打印二维码 → 扫码记录`。
- 主按钮「免费开始」→ `/register`；次按钮「我已注册」→ `/login`。
- 底部一句「不需要下载 App，手机相机直接扫」。
- 不请求用户数据。
- **新文案待补充**：本批保持现有文案，不自行改写。

**登录态**

- 有 session cookie 访问 `/` 时，`proxy.ts` 直接 `307` 到 `/garments`；不再渲染首页。
- 首页不显示数据条、最近衣物、首页统计加载/失败态。
- 登录成功与注册成功都直接进入 `/garments`。
- 写入：无；`GET /api/stats` 已删除。

### 3.2 `/login` 登录

- 表单：邮箱、密码；主按钮「登录」；下方「还没有账号？去注册」。
- 校验：邮箱格式、密码非空；错误在字段下方就地显示。
- 服务端错误：`邮箱或密码不对`（不区分哪个错）。
- 连续失败锁定：同一邮箱 15 分钟内失败 5 次后返回 `429`，按钮显示 `稍后重试（N 秒）` 并倒计时；同一 IP 另有 20 次/15 分钟上限。
- 提交中：按钮显示「登录中…」并禁用。
- 已登录访问：直接跳转 `/garments`。
- 成功：写 session cookie，跳转 `/garments`。
- 写入：仅 session cookie，不写库。
- 频率限制是单进程内存；重启清零，多实例不共享。

### 3.3 `/register` 注册

- 表单顺序：邮箱 → 验证码 → 密码（至少 8 位）→ 确认密码 → 「创建账号」。
- 「发送验证码」按钮：
  - 点击后调用 `POST /api/auth/verification-code`；
  - 成功后 60 秒冷却，按钮显示 `重新发送（N 秒）`；
  - 同一邮箱每小时最多 5 次、同一 IP 每小时最多 10 次；
  - 已注册邮箱返回 `409`；失败提示在表单顶部。
- 验证码：6 位数字；错误/过期/已用/尝试过多分别显示不同中文提示；最多尝试 5 次。
- 本地开发可用 `REGISTER_SKIP_EMAIL_VERIFICATION=1` 跳过验证码；production 忽略该开关，上线前必须为 `0`。
- 错误文案：`这个邮箱已经注册过了，直接登录吧`；`两次密码不一样`；`验证码不对`；`验证码已过期`；`验证码已经用过了`；`验证码尝试次数过多`。
- 提交中：「创建中…」并禁用；注册限流触发时按钮显示倒计时。
- 成功：创建 User → 自动登录 → 跳转 `/garments`。
- 已登录访问：跳转 `/garments`。
- 写入：`User` 一行 + `VerificationCode.used` + session cookie。

### 3.4 `/garments` 衣柜列表

- 顶部：标题「我的衣柜」+ 右侧「新增」按钮。
- 分类筛选：标题下方一条横向可滑动标签栏；固定第一项「全部」，其余来自当前衣物已有的 `category` 字段。
  - 单选、多选（并集）、再次点击取消；「全部」清空所有选中项。
  - 分类 URL 用重复参数：`/garments?category=上衣&category=裤装`；全部 = 无参数。
  - URL 为准：刷新保留当前筛选；从 `/garments` 无参数进入时默认「全部」（2026-10-20 用户确认选项 A）。
  - 窄屏只让标签栏横向滚动，不换行、不让整页横向溢出。
- 季节筛选：类别栏下方第二条同款式标签栏，固定「全部」+ 春 / 夏 / 秋 / 冬 / 其他。
  - 「其他」= season 为空/未填写；多选并集；与类别栏取交集。
  - URL 用重复 `season` 参数，和 category 同时存在：`/garments?category=上衣&season=春&season=冬`。
  - 两排切换都保留另一组筛选参数。
- 内容：卡片网格（手机 2 列 / 桌面 4 列）。卡片 = 缩略图 + 名称 + 状态徽标 + `单次 ¥x`（无数据显示「数据不足」）。
- 排序：**WORN 事件数降序；次数相同按 `seq` 降序；0 次穿着最后**。固定顺序，不提供排序控件、不写 URL；与类别/季节筛选叠加时先筛选再排序。不做关键词搜索、分页（明确砍掉，衣物量 ≤200）。
- 筛选结果为空：`没有符合条件的衣物` + 「查看全部」；本来没有衣物时仍用「衣柜还是空的」。
- 点击卡片 → `/garments/[id]`。
- 加载中：8 个骨架卡片，文案 `正在整理衣柜…`。
- 加载失败：`衣柜没打开，重试一下` + 「重试」。
- 写入：无。

### 3.5 `/garments/new` 新增衣物

分三段：**照片 → AI 建议 → 确认表单**。

1. **照片**
   - 上传区支持点击选择与手机拍照（`accept="image/jpeg,image/png"`）。
   - 客户端校验：JPG/PNG、≤10MB；不满足就地提示 `只支持 JPG/PNG，且不超过 10MB`。
   - 选好后显示预览，按钮「让 AI 看看」；也可直接「手动填写」跳过 AI。

2. **AI 建议（可失败）**
   - 调 `POST /api/ai/garment`；加载时表单骨架 + 文案 `AI 正在看这张照片…`（最长 20 秒）。
   - 返回字段：`category / primaryColor / pattern / fit / season / style` 及每个字段的置信度；`season` 为逗号组合（如 `春,秋`），`material` 仅建议；`brand` 恒为 `uncertain`。
   - 置信度 ≥ 0.7 的字段预填；< 0.7 的字段**不预填**，输入框用 `--warn` 底色标出并提示 `AI 不太确定，请自己选`。
   - AI 超时/报错：顶部黄条 `AI 没识别成功，不影响建档，手动填完就行` + 「重试 AI」；表单保持可填。
   - AI 永远不写库。

3. **确认表单**
   - 必填：照片、名称、类别。
   - 选填：颜色、图案、版型、季节（多选春/夏/秋/冬；「其他」= 未填写）、风格、材质、价格、购买日期、备注。
   - 季节用多选 chip；选中值提交为逗号字符串（如 `春,秋`），全不选提交 null/空。
   - `brand` 字段固定显示 `不确定`，不可编辑（遵守「禁止编造」）。
   - 价格允许留空；购买日期允许留空（首次录入不强制）。
   - 主按钮「确认入柜」；次按钮「取消」→ `/garments`。
   - 提交中：「正在入柜…」并禁用；失败：`没保存成功，再试一次`，保留所有已填内容。
   - 成功后显示「已入柜 G0xx」+ 两个按钮：「看看这件」→ 详情；「接着拍」→ 清空表单留在本页。
   - 写入：`POST /api/garments` → `Garment` + `Label(token)`。

### 3.6 `/garments/[id]` 衣物详情

- 顶部：大图 + 名称 + 状态徽标 + 编号 `G0xx`。
- 属性区：类别、颜色、图案、版型、季节、风格、材质、品牌、价格、购买日期、备注；季节多值显示 `春、秋`，空值显示「其他」；其他空值显示 `—`。
- CPW 区：`单次穿着成本 ¥x`；无价格或无穿着记录显示 `数据不足`。
- 事件时间线：按时间倒序，每条 `事件名 + 日期`；无事件显示 `还没有记录，扫一下衣架上的码试试`。
- 操作：
  - 「修改状态」→ 本页展开「状态记录」卡片；6 个动作与扫码页完全一致（同一 `EVENT_VALUES`、同一映射、30 秒幂等），提交后刷新状态与时间线。
  - 「编辑」→ 本页切换为编辑表单（名称/类别/颜色/图案/版型/季节多选/风格/材质/价格/购买日期/备注），保存后回到查看态。
  - 「打印标签」→ `/labels?ids=<id>`。
  - 「删除」→ 二次确认弹层：`删除后，这件衣服的记录和标签都会消失，确定吗？` 确认后删除并回 `/garments`。
- 「状态记录」卡片位置：在「单次穿着成本」与「事件时间线」之间，默认收起；供电脑端与“事后补记”使用。
- 三态：加载 `正在找这件衣服…`；不存在 → `这件衣服不在了` + 「回衣柜」；失败 → `没加载出来` + 「重试」。
- 写入：`PATCH /api/garments/[id]`、`DELETE /api/garments/[id]`、`POST /api/garments/[id]/events`。

### 3.7 `/labels` 标签拼版

- 顶部：标题「打印标签」+ 说明 `一页 24 张，选好后生成 A4 图片`。
- 衣物选择：带复选框的列表（缩略图 + 名称 + 编号），默认勾选全部 `IN_CLOSET`。
- 选择上限 **24 件**；超过时提示 `一页最多 24 张，先取消几件`，并禁用生成按钮。
- 预览：4 列 × 6 行示意（网页预览不等于最终像素，仅确认顺序）。
- 主按钮「生成并下载 PNG」：浏览器 canvas 合成 2480×3508 @300dpi → `toDataURL('image/png')` → 下载 `衣橱标签-YYYYMMDD.png`。
- 固定提示：`打印时请选「实际大小 / 缩放 100%」，不要选「适应页面」`。
- 右下角印 100mm 校验尺；文字为「衣物名 + 编号」，超出省略。
- 空数据：`还没有可以打标签的衣服` + 「去拍照建档」。
- 加载中：`正在准备标签…`；失败：`标签没生成出来` + 「重试」。
- 写入：无（token 在建档时已生成；若历史数据缺 Label，接口按需补建，仍不改衣物其他字段）。

### 3.8 `/g/[token]` 免登录扫码页

- 无登录、无 Cookie 依赖；极简服务端渲染，少 JS。
- 内容：衣物名称、缩略图、当前状态徽标、6 个动作按钮。
- 按钮与事件：

  | 按钮文案 | 事件 | 结果状态 |
  | --- | --- | --- |
  | 今天穿了 | `WORN` | 穿着中 |
  | 要洗 | `WASHED` | 待洗 |
  | 送干洗 | `DRY_CLEANED` | 待洗 |
  | 放回衣柜 | `RETURNED` | 在柜 |
  | 收起来 | `STORED` | 收纳 |
  | 卖掉了 | `SOLD` | 已退出 |

- 交互：每个按钮是原生 `<form method="post">`，隐藏 `type` 字段；提交后 303 到独立成功页 `/g/[token]/done?event=<事件>&ts=<毫秒>`，不在扫码页显示结果提示。
- 幂等：服务端若发现该衣物最近 30 秒内已有同类型事件，则不新增，仍跳成功页；刷新成功页不写库。
- 非法/失效 token、限流、写入失败：仍回 `/g/[token]?error=...`，不进入成功页。
- 隐私：只显示名称、缩略图、状态；**不显示价格、购买日期、事件时间线、用户邮箱**。
- 窄屏：按钮 2 列，不横向滚动；触控目标 ≥44px。
- 写入：`GarmentEvent` 一行 + `Garment.status` 更新。

#### `/g/[token]/done` 成功结果页

- 免登录、只读服务端页；`noindex`。
- 有效上下文（`event` 为 6 个动作之一、`ts` 在 10 分钟内）且 token 有效时显示：
  - `状态记录成功！`
  - 衣物名称
  - `当前状态：待洗`（可选）
  - 唯一按钮「点此关闭网页」。
- 直接访问、缺少/过期 `event/ts`、token 失效：显示「没有可显示的结果」+「返回首页」，不显示成功文案或衣物名称。
- 关闭按钮：先 `window.close()`；约 300ms 后页面仍在（系统相机打开的标签页通常如此）时，同按钮变为「返回首页」，并提示手动关闭或返回首页。
- 刷新只重新读取，不新增事件；不使用数据库写入。

### 3.9 `/legal/privacy` 隐私协议

- 免登录静态页；极简页头（品牌 + 登录/注册），正文单列，最大宽度约 820px。
- 顶部：草案提示 + 版本/生效日期/更新日期；有效期与主体信息用高亮「待补充」。
- 目录：引言与适用范围、运营主体、服务器与跨境、收集的数据、用途、AI/第三方、保存期限、用户权利、数据安全、更新、备案、联系。
- 必须明确：**服务器位于香港、用户数据存储于香港、属于数据跨境传输**。
- 必须覆盖：收集哪些数据、用途、保存期限、查询/更正/删除/导出路径、联系方式。
- 主体全称、邮箱、生效日期、备案信息等一律「待补充」，不编造法律条款编号或承诺。
- 页尾：返回登录、返回注册；浏览器返回也可用。

### 3.10 `/legal/terms` 用户协议

- 免登录静态页，与隐私协议同一套 `.legal-*` 样式。
- 目录：协议主体与生效、服务说明、账号与安全、用户内容与授权、使用规则、AI 限制、数据存储与跨境、知识产权、变更/终止、免责与责任限制、协议更新、适用法律（待补充）、联系方式。
- 必须再次明确：**服务器位于香港、用户数据存储于香港、属于数据跨境传输**；详细规则链接到隐私协议。

## 4. 数据写入点

| 操作 | 接口 | 写表 | 说明 |
| --- | --- | --- | --- |
| 注册 | `POST /api/auth/register` | `User` | 邮箱唯一；密码哈希 |
| 登录 | `POST /api/auth/login` | 无 | 只写 session cookie |
| 退出 | `POST /api/auth/logout` | 无 | 清 cookie |
| 新增衣物 | `POST /api/garments` | `Garment` + `Label` | 同事务；token 12 位 base62 |
| AI 识别 | `POST /api/ai/garment` | 无 | 只返回建议；调用计数只写日志 |
| 编辑衣物 | `PATCH /api/garments/[id]` | `Garment` | 只允许改自己的 |
| 详情页补记状态 | `POST /api/garments/[id]/events` | `GarmentEvent` + `Garment` | 登录态；仅自己的；30 秒幂等；与扫码动作同映射 |
| 删除衣物 | `DELETE /api/garments/[id]` | `Garment` + `GarmentEvent` + `Label` | 级联删除；再删照片文件 |
| 生成标签 | `GET /api/labels?ids=...` | 无（缺失时补 `Label`） | 只读衣物与 token |
| 扫码动作 | `POST /api/g/[token]/action` | `GarmentEvent` + `Garment` | 同事务；幂等窗口 30 秒 |

> 统一返回：成功 `{ ok: true, data }`；失败 `{ ok: false, code, msg }`，HTTP 状态码同时正确。
> 所有读接口都必须带 `userId` 条件（扫码接口用 token 限定单件）。

## 6. 状态与事件（沿用 DECISIONS §3）

5 状态：`IN_CLOSET` 在柜 / `WORN` 穿着中 / `TO_WASH` 待洗 / `STORED` 收纳 / `RETIRED` 已退出。

6 事件 → 状态：`WORN→WORN`、`WASHED→TO_WASH`、`DRY_CLEANED→TO_WASH`、`RETURNED→IN_CLOSET`、`STORED→STORED`、`SOLD→RETIRED`。

- 状态徽标颜色：在柜 `--ok`，穿着中 `--accent`，待洗 `--warn`，收纳 `--ink-muted`，已退出 `--danger`。
- 事件只增不改；状态是事件的结果，不单独手改。

## 8. 关键实现约定（Stage 2 用）

| 项 | 约定 |
| --- | --- |
| 会话 | 签名 cookie（HMAC-SHA256，`SESSION_SECRET`），HttpOnly + SameSite=Lax + 生产 Secure，30 天；不新增会话表 |
| 密码 | Node 内置 `crypto.scrypt` 加盐哈希，不引入 bcrypt 依赖 |
| 登录限流 | 邮箱 5 次/15 分钟后锁定；IP 20 次/15 分钟后锁定 |
| CSRF | SameSite=Lax + 写操作校验 `Origin` 与 `APP_BASE_URL` 同源 |
| 图片 | 存 `uploads/garments/<id>.<ext>`（Git 忽略）；读取走带鉴权的路由，不直接暴露目录 |
| 图片校验 | 前后端双校验：扩展名/MIME + 魔数 + ≤10MB |
| API 封装 | 前端统一请求函数，永不向页面抛异常；超时 20s；返回 `{ ok, data, code, msg }` |
| 错误码 | `UNAUTHORIZED` / `FORBIDDEN` / `NOT_FOUND` / `VALIDATION` / `AI_UNAVAILABLE` / `RATE_LIMITED` / `INTERNAL` |
| AI adapter | 20s 超时、失败重试 1 次、再失败 `AI_UNAVAILABLE`；`response_format: json_schema`；关闭深度思考；累计 300 次打警告 |
| 渲染 | 受保护页用服务端组件读取会话；Next 16 Cache Components 下对确实需要阻塞读取的受保护页显式 `instant = false`；扫码页服务端渲染，保持极简 |
| 测试 | 只写单元测试：状态映射、CPW、token 生成/唯一性、排版容量 24 格；不写 Playwright |
