## 1. 范围

### 1.1 一句话

给现实衣柜建一份数字档案：拍照建档 → 打印二维码贴到衣架 → 手机系统相机扫码记录穿着。目标用户/定位/竞品不在此复述，见 [`PRODUCT.md`](PRODUCT.md)。

### 1.2 已实现的 12 个页面

| # | 路由 | 用途 | 登录要求 |
| --- | --- | --- | --- |
| 1 | `/` | 游客落地页；已登录访问自动去 `/garments` | 否 |
| 2 | `/login` | 邮箱 + 密码登录 | 否 |
| 3 | `/register` | 注册并自动登录 | 否 |
| 4 | `/garments` | 自己的衣柜列表；按类别筛选 | 是 |
| 5 | `/garments/new` | 上传照片 → AI 建议 → 确认入柜 | 是 |
| 6 | `/garments/[id]` | 详情、属性、事件时间线、编辑/删除、补记状态 | 是 |
| 7 | `/labels` | 选择衣物 → 生成 A4 标签 PNG | 是 |
| 8 | `/g/[token]` | 免登录扫码记录 | 否（凭 token） |
| 9 | `/legal/privacy` | 隐私协议草案（数据、跨境、权利） | 否 |
| 10 | `/legal/terms` | 用户协议草案（服务、账号、责任） | 否 |
| 11 | `/outfits` | 固定搭配列表与页内新建 | 是 |
| 12 | `/outfits/[id]` | 搭配详情、编辑、删除 | 是 |

> 原约定页面数量上限为 8；v0.4 因隐私协议/用户协议合规需要新增 2 个静态法务页，当时共 10 页。该例外只适用于法务静态页（见 `docs/DECISIONS.md` D17）。
> v0.11 经确认将页面上限上调到 12：新增 `/outfits` 与 `/outfits/[id]` 两个搭配页（DECISIONS D24）。
> `/g/[token]/done` 是扫码结果子页，不单独计入 12 页清单。

### 1.3 已实现的 4 个核心功能

1. AI 拍照建档
2. 衣柜列表与详情
3. 标签生成与 A4 打印
4. 免登录扫码记录状态

另含登录/注册与游客落地页。

## 2. 功能规格与验收标准

### F1 账号与会话

**已实现**

- 注册：邮箱唯一、密码至少 8 位；先 `POST /api/auth/verification-code` 获取 6 位验证码，再用 `{ email, password, code }` 注册；验证码有效期 10 分钟、最多尝试 5 次；正确后创建 `User`、标记验证码已用并直接写 session 进入 `/garments`。
- 验证码存储：`VerificationCode` 表，字段含邮箱、哈希、用途、过期时间、尝试次数、是否已用、创建时间、请求 IP；只存 scrypt 哈希，不存明文。
- 邮件发送：adapter 抽象；已配置 163 SMTP（`smtp.163.com:465` + 授权码）真实发信；无配置时可用 console 模式（仅非 production）把验证码打到服务端日志。
- 本地开发开关：`REGISTER_SKIP_EMAIL_VERIFICATION=1` 且非 production 时可跳过验证码；默认 `0`，production 忽略并要求验证码。
- 登录：邮箱 + 密码；失败返回统一文案「邮箱或密码不对」；同一邮箱 15 分钟内失败 5 次锁定，同一 IP 15 分钟内失败 20 次锁定（单进程内存计数）。
- 忘记密码：登录页展开重置面板，输入注册邮箱获取 6 位验证码，再设置新密码；`POST /api/auth/password-reset-code` 与 `POST /api/auth/reset-password`；复用 `VerificationCode`（purpose=`RESET_PASSWORD`），验证码同样 10 分钟、最多 5 次尝试；未注册邮箱也返回相同成功文案，避免枚举；重置成功不自动登录，回登录页用新密码登录。
- 验证码/注册限流：发送冷却 60 秒、同一邮箱每小时 5 次、同一 IP 每小时 10 次；注册同一邮箱每小时 5 次、同一 IP 每小时 10 次；重置密码发送与提交分别有独立限流。
- 会话：HMAC-SHA256 签名 cookie，HttpOnly、SameSite=Lax、生产环境 Secure、30 天；不建 Session 表。
- 退出：清 cookie。
- 受保护页面：`/garments*`、`/labels` 无 session cookie 时由 `proxy.ts` 307 到 `/login`；页面/接口内部还会再次校验签名与用户。
- demo 账号 `demo@example.com / demo1234` 继续可登录（不特殊绕过限流）。

**验收标准**

- [ ] 控制台模式下发送验证码返回 `200`，服务端日志出现 6 位码；数据库 `codeHash` 不等于明文。
- [ ] SMTP 模式（163）发送验证码返回 `200`，真实邮箱可收到；服务端日志不打印验证码。
- [ ] 正确验证码注册返回 `201`、自动登录；错误码/过期码/已使用码/尝试过多分别返回不同中文提示。
- [ ] 同一邮箱 60 秒内重复发送返回 `429`，并带剩余秒数；同一 IP 超过 10 次/小时返回 `429`。
- [ ] 同一邮箱每小时超过 5 次发送返回 `429`。
- [ ] 缺少验证码、验证码格式不对、邮箱格式错、密码不足 8 位返回 `400`；重复邮箱返回 `409`。
- [ ] 同一邮箱 15 分钟内连续失败 5 次后第 6 次登录返回 `429` + 剩余秒数；IP 维度达到 20 次同样锁定。
- [ ] 登录页可展开「忘记密码」；未注册邮箱请求验证码也返回相同成功文案；真实用户可收到重置密码验证码。
- [ ] 用正确验证码 + 新密码重置返回 `200`，旧密码失效、新密码可登录；错误/过期/已用验证码分别返回中文提示。
- [ ] 重置密码验证码不进入注册用途；注册验证码也不能用于重置密码。
- [ ] demo 账号正确密码登录返回 `200`。
- [ ] `REGISTER_SKIP_EMAIL_VERIFICATION=1` 在 development 可无验证码注册；production 不生效。
- [ ] 未登录访问 `/garments` 返回 `307` 到 `/login`；未登录访问 `/api/garments` 返回 `401`。
- [ ] 退出后再访问 `/api/auth/me` 返回 `401`。
- [ ] cookie 被篡改或过期时按未登录处理。

### F3 AI 拍照建档

**已实现**

- 上传：只接受 JPG/PNG（按文件魔数判断，不信任扩展名）；文件 ≤10MB。
- 服务端压缩：`sharp` 按 EXIF 旋正、等比缩到 1440×1920 以内、不放大、JPEG q82、透明铺白；原图不落盘。
- 临时图：保存到 `uploads/tmp/<userId>/<token>`，返回 32 位 hex `imageToken`。
- AI：可点「让 AI 看看」，也可「手动填写」跳过（`skipAi=1`）。
- AI 输出字段：`category / primaryColor / pattern / fit / season / style` + `material`（仅建议）+ 每字段 `confidence`；`brand` 恒为 `uncertain`。
- 季节：多选春 / 夏 / 秋 / 冬；未填写归为「其他」（空值）。SQLite 中以逗号分隔字符串存储（如 `春,秋`），AI 输出同样用逗号组合；旧值迁移：`春秋→春,秋`、`四季→春,夏,秋,冬`。
- 低置信度：`category / primaryColor / pattern / fit / season / style` 中 `confidence < 0.7` 的字段不预填，界面标黄并提示「AI 不太确定，请自己选」；`material` 是建议字段，低置信度时仍可能预填，但会标黄。
- 失败降级：AI 未配置/超时/报错时接口仍返回 `200` 和 `imageToken`，`ai.ok=false`；用户可继续手填。
- 确认入柜：`POST /api/garments`，同一事务创建 `Garment` + `Label`；按用户分配 `seq`，编号显示为 `G001` 形式；初始状态 `IN_CLOSET`。
- 成功后两个入口：「看看这件」→ 详情；「接着拍」→ 清空表单留在本页。

**验收标准**

- [ ] 非 JPG/PNG 或 >10MB 的图片被前端与服务端同时拒绝，文案「只支持 JPG/PNG，且不超过 10MB」。
- [ ] 上传成功后返回 `imageToken`；`skipAi=1` 时不调用 Ark，`ai=null`。
- [ ] AI 成功时返回符合白名单的 6 个字段、`material`、`brand="uncertain"`、`confidence` 0–1；季节不出现「春秋」「四季」。
- [ ] 新增页季节可多选春/夏/秋/冬；「其他」清空为未填写；提交后数据库存逗号组合。
- [ ] AI 失败（无 key / 超时 / 非 2xx）时，用同一个 `imageToken` 仍能创建衣物。
- [ ] 名称、类别缺失时返回 `400`；`imageToken` 不存在/过期时返回 `400`，文案「照片过期了，请重新上传」。
- [ ] 创建成功返回 `201` 和 `Gxxx`；`Garment` 与 `Label` 同时存在，`status=IN_CLOSET`。
- [ ] 低置信度字段不被自动填入；`brand` 不可编辑，始终显示「不确定」。
- [ ] 创建后列表与详情可看到该衣物；「接着拍」清空所有输入。

### F4 衣柜列表、详情、编辑、删除、补记状态

**已实现**

- 列表：只查当前 `userId` 的衣物，最多 200 件；**排序为 WORN 事件数降序，次数相同按 `seq` 降序**（0 次穿着排最后）；卡片含照片、编号、名称、类别、状态、单次 CPW。
- 排序固定，不提供排序控件，不写 URL；与类别筛选叠加时**先筛选、再在结果内排序**。`GET /api/garments` 保持 `seq` 倒序，供标签页复用，不受此排序影响。
- 分类筛选：顶部横向可滑动标签栏，固定「全部」；类别来自当前衣物已有的 `category`，支持单选/多选并集/取消；URL 用重复 `category` 参数，全部 = 无参数；从 `/garments` 无参数进入默认全部，刷新保留当前 URL 筛选。
- 季节筛选：类别栏下方第二排标签栏，固定春/夏/秋/冬/其他；「其他」匹配 season 为空/未填写；多选并集，与类别筛选取交集；URL 用重复 `season` 参数（如 `?category=上衣&season=春&season=冬`），刷新保留、返回键可用。
- 详情：按 `id + userId` 查询；展示图片、属性、品牌「不确定」、价格、购买日期、备注、CPW、事件时间线（最多 100 条）；季节多值显示为 `春、秋`，空值显示「其他」。
- 状态记录：详情页「修改状态」展开 6 个动作，文案/顺序复用扫码页的 `EVENT_VALUES`；`POST /api/garments/[id]/events` 校验登录与归属，30 秒内同事件幂等；成功后刷新状态与时间线。
- 编辑：`PATCH /api/garments/[id]`，支持名称/类别/颜色/图案/版型/季节/风格/材质/价格/购买日期/备注；不改照片、不改状态。
- 删除：`DELETE /api/garments/[id]`，数据库级联删除 `GarmentEvent`、`Label`、`OutfitItem`，再删除照片文件；搭配本身保留，变空时页面提示；前端二次确认。
- 越权：查询/修改/删除/补记状态都带 `userId`，别人的衣物返回 `404`。

**验收标准**

- [ ] 列表只出现当前账号的衣物；按 WORN 次数降序，次数相同按 `seq` 降序。
- [ ] 0 次穿着的衣物排在最后。
- [ ] 类别栏与季节栏同时存在；季节栏可横向滑动，行为与类别栏一致（多选并集、全部清空）。
- [ ] 类别与季节同时选中时取交集，结果数量正确；season 为空的衣物只在「其他」或「全部」下出现。
- [ ] 与类别筛选叠加时先筛选、再在结果内排序。
- [ ] 页面没有排序控件；`/api/garments` 与 `/labels` 选择列表顺序不变。
- [ ] 分类栏可横向滑动，窄屏不换行、整页不横向溢出。
- [ ] 单选只剩该类别，多选为并集，再次点击取消；「全部」置顶且清空其他选中项。
- [ ] 筛选结果为空时显示「没有符合条件的衣物」+「查看全部」，不是空白页。
- [ ] 筛选状态写入 URL（`?category=上衣&season=春&season=冬`）；浏览器返回键恢复上一筛选；无参数进入默认全部。
- [ ] 刷新保留当前 URL 筛选（2026-10-20 确认按选项 A；原「刷新回全部」改为「无参数进入默认全部」）。
- [ ] 详情页正确显示属性、CPW（无数据时「数据不足」）和事件时间线。
- [ ] 详情页可见「修改状态」；展开后 6 个动作文案/顺序与扫码页完全一致。
- [ ] 同一动作连续提交两次：30 秒内第二次不新增事件；不同动作按映射更新状态并新增一条时间线。
- [ ] 补记成功后详情页状态与时间线立即刷新。
- [ ] 未登录访问详情页仍跳转 `/login`。
- [ ] `PATCH` 后详情页刷新可见新值；非法枚举值/价格/日期返回 `400`。
- [ ] `DELETE` 后列表不再出现该衣物，相关 `GarmentEvent`、`Label` 与照片文件被删除。
- [ ] 用其他账号的衣物 id 访问详情/PATCH/DELETE/事件接口均返回 `404`。
- [ ] 删除前必须经过二次确认。

### F5 标签生成与 A4 打印

**已实现**

- `/labels` 默认勾选全部 `IN_CLOSET` 衣物；可通过 `?ids=` 预选；最多 24 件。
- `GET /api/labels?ids=...` 返回 `baseUrl` 与每件的 `name/code/token`；缺失 `Label` 时按需补建（不改衣物其他字段）。
- 浏览器端 canvas 生成 2480×3508 PNG @300dpi：
  - 4 列 × 6 行，共 24 格；
  - 二维码 30mm（容错 M），内容为 `${APP_BASE_URL}/g/{token}`；
  - 每格文字「衣物名 + Gxxx」，8pt，超出省略；
  - 右下角 100mm 校验尺；
  - 自动下载 `衣橱标签-YYYYMMDD.png`。
- 页面固定提示打印选「实际大小 / 缩放 100%」。

**验收标准**

- [ ] 默认选择在柜衣物；超过 24 件时阻止继续选择/生成。
- [ ] 生成图片尺寸正好 2480×3508，格式 PNG。
- [ ] 24 个单元格都在页边距内，互不重叠；二维码边长约 354px（30mm@300dpi）。
- [ ] 二维码解码结果为完整 URL（含 `APP_BASE_URL` 与 12 位 token）。
- [ ] 页面上有 100mm 校验尺与打印缩放提示。
- [ ] 生成后浏览器实际下载 PNG；预览可见。
- [ ] 真实打印/裁剪/贴衣架/手机扫码未在本机验收（见 `tasks/003-print-scan-g4.md`）。

### F6 免登录扫码记录

**已实现**

- `/g/[token]` 不要求登录，只凭 12 位 base62 token 定位单件衣物。
- 展示：名称、缩略图、当前状态；不展示价格、购买日期、事件时间线、用户邮箱。
- 6 个动作：`WORN` 今天穿了 / `WASHED` 要洗 / `DRY_CLEANED` 送干洗 / `RETURNED` 放回衣柜 / `STORED` 收起来 / `SOLD` 卖掉了。
- 每个动作是原生 `<form method="post">` 到 `/api/g/[token]/action`；成功后 `303` 到独立成功页 `/g/[token]/done?event=<事件>&ts=<毫秒>`。
- 成功页：无登录、只读；显示「状态记录成功！」、衣物名称、当前状态，唯一按钮「点此关闭网页」；浏览器拒绝关闭时按钮改为「返回首页」并显示兜底文案。
- 直接访问 `/g/[token]/done` 或缺少/过期的 `event/ts` 时显示「没有可显示的结果」，不显示成功文案与衣物名称。
- 状态映射：`WORN→WORN`、`WASHED/DRY_CLEANED→TO_WASH`、`RETURNED→IN_CLOSET`、`STORED→STORED`、`SOLD→RETIRED`。
- 幂等：同一衣物 30 秒内重复同事件不新增事件，仍跳成功页；成功页刷新不写库。
- 详情页另提供登录态等价入口（F4），扫码页行为不变。
- 限流：同一 IP+token 每分钟最多 20 次动作。
- 非法/失效 token：友好页，不暴露 token、SQL、堆栈；不进入成功页。
- 首页缩略图接口 `/api/g/[token]/photo` 同样只凭 token。

**验收标准**

- [ ] 无 cookie 打开 `/g/{token}` 返回 `200` 并显示 6 个动作。
- [ ] 点「今天穿了」→ `303` 到 `/g/{token}/done?event=WORN&ts=...`，`GarmentEvent` 新增 1 条，`status=WORN`。
- [ ] 成功页无登录可访问，显示「状态记录成功！」、衣物名称与当前状态；刷新不新增事件。
- [ ] 成功页点击「点此关闭网页」；浏览器不允许关闭时按钮变「返回首页」，并显示手动关闭/返回兜底文案。

### F8 固定搭配（Outfits）

**已实现**

- 一套搭配含 1–4 件衣物；超过 4 件时客户端阻止并提示，服务端也返回 400；少于 1 件禁止保存。
- 搭配必须有名称（trim 后 1–40 字）；备注可留空，最多 200 字。
- 搭配有独立页面：`/outfits` 列表 + 页内新建；`/outfits/[id]` 详情、编辑（改名/备注/换件）、删除。
- 页面显示名称、备注、最多 4 张衣物原图；**不生成缩略图拼图**，不提供分享链接。
- 数据存 `Outfit` + `OutfitItem` 两张表；`OutfitItem.position` 保存顺序；同一搭配不能重复同一件衣物。
- 全部查询/写入按 `userId` 归属校验；访问他人搭配返回 404。
- 删除衣物时，`OutfitItem` 通过外键级联自动移除；搭配因此变空时保留搭配，页面提示「这套搭配已空」；衣物删除成功提示受影响/变空搭配数。
- 空搭配可只改名称/备注（不传 items），也可补充衣物或直接删除。
- **不做**：拼图/海报、分享链接、一键记录穿着、搭配推荐、AI 生成搭配；不与扫码联动。

**验收标准**

- [ ] 从站点头部导航可进入 `/outfits`；列表只显示当前账号的搭配。
- [ ] 新建时可选择 1–4 件衣物并填写名称/备注；选到第 5 件被阻止并显示中文提示。
- [ ] 少于 1 件不能保存；创建 0 件/5 件 API 返回 400。
- [ ] 列表显示名称、备注、最多 4 张原图小图；空搭配显示提示。
- [ ] 详情页可编辑改名、备注、换件；可二次确认删除搭配。
- [ ] 越权读取/编辑/删除他人搭配返回 404。
- [ ] 删除被引用衣物后，搭配中不再出现该件且不报错；变空搭配保留并提示。
- [ ] `GET /api/outfits`、`GET/PATCH/DELETE /api/outfits/[id]` 均要求登录并按 userId 归属校验。
- [ ] `npm test` / `npm run build` 通过。

## 3. 跨功能硬规则

- **AI 不直接写库**：AI 只返回建议；写库只发生在用户确认后的普通 CRUD 接口。
- **禁止编造**：`brand` 恒为 `uncertain`；`material` 仅建议；6 个枚举字段在低置信度（<0.7）时不预填。
- **AI 失败必须可降级**：无 key/超时/报错时用户仍可手动完成建档。
- **确定性任务不用 AI**：二维码编码用 `qrcode`，解码交给手机系统相机。
- **归属强制**：所有衣物查询/修改/删除都过滤 `userId`；扫码接口用 token 限定单件。
- **统一响应**：成功 `{ ok: true, data }`；失败 `{ ok: false, code, msg }`，HTTP 状态码同时正确。
- **图片限制**：JPG/PNG、≤10MB、服务端压缩到 1440×1920 内、JPEG q82；原图不落盘。
