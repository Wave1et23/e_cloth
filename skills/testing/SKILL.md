# SKILL · 测试（testing）

> 适用：新增/修改纯逻辑、限流规则、验证码规则、状态映射、排版计算时。
> 项目测试栈：**Node 原生 `node --test`**，直接跑 `.ts`，没有 jest / vitest / Playwright。

## 一、最容易踩的坑：新测试文件不会自动被执行

`package.json` 的 `test` 脚本是**逐个列出文件**的，不是 glob：

```
"test": "node --test tests/unit/status.test.ts tests/unit/cost.test.ts ..."
```

**新增一个 `tests/unit/xxx.test.ts` 后，必须手动把它追加到这条命令里**，否则 `npm test` 显示全绿但新测试根本没跑。当前基线：**49 项通过**。

## 二、只写什么、不写什么

| 写 | 不写 |
| --- | --- |
| 纯函数：状态映射、CPW 计算、token 生成、排版格数、限流窗口、验证码规则、筛选并集 | 需要数据库的集成测试 |
| 边界值与非法输入 | 组件渲染快照 |
| 幂等判断的纯函数部分 | 真实 HTTP（用 curl 手工验） |

需要 DB / HTTP 的验证走**手工命令**，并把输出贴进 `docs/ITERATION_LOG.md`。

## 三、边界用例库（改这些模块时逐条过一遍）

**通用**
- 空值 / `null` / `undefined` / 空字符串
- 超长字符串（1KB、100KB）
- 数字边界：0、负数、最大值、`priceCents` 为 `null` 时 CPW 显示「数据不足」而非 0
- 非法输入：错枚举值、大小写、前后空格、全角字符

**token / 扫码**
- 非法 token、已失效 token、超长 token
- 同一事件 30 秒内重复 → 只写一条
- 中断一次后再次请求 → 仍只写一条

**限流 / 验证码**
- 恰好第 N 次（阈值边界）：第 N 次通过、第 N+1 次拒绝
- 窗口过期后恢复
- 冷却剩余秒数返回为整数且 > 0
- 验证码：错误、过期、已用、尝试次数达上限 → 四种提示必须不同
- 验证码只存哈希，不得出现明文

**标签排版**
- 0 件 / 1 件 / 24 件 / 25 件（超出上限要提示而不是静默截断）
- 单元格尺寸与网格数的换算不得因取整产生溢出

**分类筛选**
- 无参数 → 全部
- 单选 / 多选并集 / 重复参数去重
- 未知分类、筛选结果为空

## 四、验证顺序（每次改完都跑）

```
1. npm test              → 期望 49 passed（新增测试后数字要同步更新基线）
2. npm run build         → exit 0（预渲染错误只在这里暴露）
3. curl 关键接口          → 401 / 307 / 201 / 429 各一条
4. headless Chrome 截图   → 仅当改了布局，存 backup/screens/
5. 更新 docs/ITERATION_LOG.md 的验证证据
```

## 五、报告格式

```
【跑了什么】npm test → 52 passed / 0 failed
【关键用例】新增 3 条：阈值边界、窗口过期、空结果
【没覆盖什么】DB 事务回滚（靠手工 curl 验证，见 ITERATION_LOG）
```
