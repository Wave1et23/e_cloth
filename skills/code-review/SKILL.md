# SKILL · 代码审查（code-review）

> 适用：每个 feature 完工后、提交前自查或让另一个 Agent 审查时。
> 原则：只报**能定位到文件与行为**的问题；不写"建议优化性能"这类无法验证的空话。

## 一、必查清单（按风险排序）

### 1. 越权与鉴权

- [ ] 每个读写接口都校验 `userId` 归属，不能只靠前端不传别人的 id
- [ ] 未登录访问受保护页面 → `307 /login`；访问受保护接口 → `401`
- [ ] `/g/[token]/action` 免登录是**刻意设计**（capability URL），但作用域只能落到该 token 对应的**单件衣物**
- [ ] 不返回他人数据，也不返回 `email` / `passwordHash` / `sessionSecret` 等隐私字段

### 2. 幂等与重复提交

- [ ] 扫码页与详情页写入事件都走 30 秒同事件幂等
- [ ] 连点按钮不产生两条事件
- [ ] 注册/发码接口重复提交不会造出多条有效记录

### 3. 降级与错误处理

- [ ] AI 接口失败时，用户仍能手动完成建档
- [ ] 外部服务（Ark / SMTP）超时返回明确错误码，不把底层异常抛给页面
- [ ] 错误文案是中文人话，不含堆栈、文件名、SQL

### 4. 数据一致性

- [ ] 写 `GarmentEvent` 与更新 `Garment.status` 在同一事务
- [ ] 创建衣物时 `Garment` + `Label` 在同一事务；失败回滚已落盘的照片
- [ ] 删除衣物时级联删事件/标签，并删除照片文件

### 5. Next.js 16 特有点

- [ ] 读 cookie / 数据库的页面有 `export const instant = false` 或等价处理
- [ ] `getCurrentUser()` 等依赖时间/会话的调用按项目既有方式处理（已有 `connection()` 约定），不要引入 `Date.now()` 造成预渲染不稳定
- [ ] 改动后 `npm run build` 通过（预渲染错误只在 build 暴露）

### 6. 密钥与依赖

- [ ] 没有把真实 key 写进代码、文档、`.env.example`
- [ ] 新增依赖有必要理由；能用现有依赖就不新增
- [ ] `git diff` 里没有 `.env`、`*.db`、`uploads/`

## 二、输出格式

```
【阻断】文件:行 — 问题一句话 — 触发路径 — 建议改法
【应修】……
【可留】……（说明为什么现在不改）
```

## 三、验证要求

审查结论必须能用一条命令或一个 URL 复现，不接受"看起来没问题"。
