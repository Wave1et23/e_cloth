# 开发计划·人话版

> 这份文档只有一件事要做：**让你知道每周该干什么。**
> 术语看不懂不用管，第四节有小词典；看完这页就够开工了。
> 详细的规范在 `02-开发计划与排期.md`，那是「用到才翻」的参考手册，不是要背的书。

---

## 一、这 4 周到底要做出什么东西

一句话：**一个网站，加上贴在衣架上的二维码。**

用户拿手机拍一件衣服 → AI 自动填好衣服信息 → 用户点确认 → 这件衣服进了网站 → 网站给它一个二维码 → 打印出来贴衣架上 → 以后每次穿完，用手机相机扫一下二维码 → 点「穿了」→ 网站上这件衣服的穿着次数 +1。

就这些。**总共 4 个功能：**

| # | 功能 | 大白话 |
| --- | --- | --- |
| 1 | **AI 建档** | 拍张照片，AI 帮你把"类别、颜色、图案、季节"都填好，你只需要看一眼点确认 |
| 2 | **衣柜列表** | 像相册一样翻自己的衣服，点开能看详情 |
| 3 | **二维码标签** | 给每件衣服生成一个码，打印出来贴衣架 |
| 4 | **扫码页** | 手机扫一下，出现几个按钮，点「穿了」，网站数字就变了 |

**别的都不做。** 不做好看的首页、不做搭配推荐、不做天气、不做社区、不做图表。

为什么只做四个？因为**比赛看的是"这条线能不能完整跑通"，不是"功能有几个"。** 四个功能全通 > 十五个功能各通一半。

## 二、4 周，每周只干一件大事

| 周 | 这一周只干这一件事（大白话） | 周末必须能演示 | 怎么算过关 |
| --- | --- | --- | --- |
| **第 6 周** | **先做一条最细的线，从头通到尾** | 拍照 → AI 填表 → 存进网站 → 生成二维码 → **手机真的扫开** → 点「穿了」→ 状态变了 | 手机录一段 30 秒视频，能看完整条线 |
| **第 7 周** | **把这条线做得好用一点** | 注册登录、能连续建档 10 件衣服、能看列表和详情 | 你自己用手机建 10 件，别卡住 |
| **第 8 周** | **把二维码真的贴到衣架上** | 打印标签、贴衣架、扫、状态变、首页数字 +1 | 打印出来的纸上，真手机扫得开 |
| **第 9 周** | **不再做功能，只做"证明"** | 考一考 AI 准不准（20 件衣服）、找 3 个人试用、上线、彩排演示 | 公网能打开 + 有一份 AI 准确率报告 |

第 10–11 周：**只修 bug，加任何功能都不许。**

### 第 6 周最难，必须撑过去

第 6 周的做法跟一般人想的不一样 —— 不是"先做登录、再做列表、再做 AI……"，而是**先把最细的一条线打通**：

```
拍一张照片 → AI 返回结果 → 存数据库 → 列表里出现
→ 生成一个二维码 → 打印 → 手机扫开 → 点一下 → 状态变了
```

这条线（我在文档里叫"**垂直切片**"）第 6 周打通了，后面三周就只是"把它做宽一点"。**打不通，后面全乱。**

所以第 6 周的页面会很丑、没有登录、只有一个字段 —— **这是故意的，别去美化它。**

## 三、每天大概花多久

| 情况 | 每天 |
| --- | --- |
| 正常日 | 3–5 小时 |
| 卡壳的日子 | 可能 8 小时 |
| 第 9 周 | 会轻松一些，主要是跑测试和整理材料 |

**每天收工前 10 分钟，只做三件事：**

1. 代码存一下（commit）
2. 今天用过的 AI 指令（就是那个"给 AI 的提示词"）复制到 `docs/AI-USAGE-LOG.md`，**失败的也要存**
3. 想好明天第一件事

第 2 条看起来没用，其实是**比赛打分的重要材料**。每天 5 分钟，最后省几十个小时。

## 四、术语小词典（看不懂词的时候来查）

### 组 1：跟数据库有关

| 词 | 大白话 |
| --- | --- |
| **数据库** | 存数据的地方，可以理解成很多张 Excel 表 |
| **Schema（表结构）** | 每张表有哪些列。比如"衣服表"有：名称、颜色、价格 |
| **ORM / Prisma** | 用 JS 代码操作数据库的工具，不用手写 SQL |
| **Migration（迁移）** | 你改了表结构，把改动同步进数据库的动作 |
| **seed（种子数据）** | 提前塞进去的假数据，让演示时网站不是空的 |
| **字段** | 表里的一列，比如"颜色" |

### 组 2：跟网站有关

| 词 | 大白话 |
| --- | --- |
| **API / 接口** | 一个网址对应一段后端逻辑。前端问它要数据，它回数据 |
| **前端 / 后端** | 前端 = 你眼睛看到的页面；后端 = 服务器上算东西的部分 |
| **Next.js** | 一个工具，能同时写前端和后端，省得搞两套 |
| **Session / JWT** | 记录"你已经登录了"的小凭证 |
| **登录 / 鉴权** | 确认"你是谁"、"你有没有权限看这个" |
| **部署** | 把网站从你电脑搬到服务器上，让别人也能打开 |
| **域名 / HTTPS** | 域名 = 网址；HTTPS = 网址前面那个小锁，**要扫码必须配，不然手机打不开** |
| **Nginx** | 服务器上的"门卫"，负责收请求再转给你的程序 |
| **pm2** | 让网站后台一直开着的工具（不然你关掉电脑它就停了） |
| **`.env` 文件** | 存密码、密钥的地方，**千万别上传到 GitHub** |

### 组 3：跟 AI 有关

| 词 | 大白话 |
| --- | --- |
| **Prompt（提示词）** | 你给 AI 下指令的那段话 |
| **Structured Output** | 要求 AI 必须按固定格式回答（比如必须返回一张表），不能随便说话 |
| **JSON** | 一种数据格式，长这样：`{"颜色": "灰", "类别": "卫衣"}` |
| **confidence（置信度）** | AI 对每个判断的把握，0~1。0.9 就是"挺确定" |
| **uncertain** | AI 承认"我判断不出来"。**别让 AI 瞎编，宁可让它说不会** |
| **Human-in-the-loop** | AI 只给建议，人来点头才存进去。**这是我们的核心原则** |
| **降级 / fallback** | AI 挂了或超时的时候，用户还能手动填完，不至于卡死 |
| **Eval（评测）** | 拿固定的一批题考 AI，算准确率。比如 20 件衣服，看类别猜对几件 |
| **Ground Truth** | 你自己手动标注的"正确答案"，用来跟 AI 的答案对 |
| **Skill** | 写给 AI 看的一份工作规范，比如"改识别功能前先看表结构" |
| **AGENTS.md** | 告诉 AI"这个项目的规矩是什么"的文件，省得每次重新解释 |

### 组 4：跟二维码和打印有关

| 词 | 大白话 |
| --- | --- |
| **二维码生成** | 一段代码，把网址变成黑白方块图。5 行代码搞定 |
| **二维码识别** | **不用你写。手机相机自带**，对着扫就会跳出链接 |
| **token（令牌）** | 一串随机字符，代替 ID 用。比如 `/g/8Kd93sa` 里的 `8Kd93sa`。**随机的好处：别人猜不到** |
| **capability URL** | "拿到链接就能用"的网址，**不需要登录**。我们的扫码页就是这样 |
| **容错级别** | 二维码被磨花一块还能不能扫。设成 M 或 H 比较保险 |
| **`@page`** | 一条 CSS 规则，告诉浏览器"按 A4 纸来打印"。**用它代替生成 PDF** |
| **CDN / 对象存储** | 专门存图片的服务。**我们不用**，直接存服务器硬盘 |

### 组 5：跟流程有关

| 词 | 大白话 |
| --- | --- |
| **MVP** | 最小可用版本 —— 能跑通的最小那一套 |
| **PRD** | 需求文档，写清楚"要做什么" |
| **垂直切片** | 先做一条最细的从头到尾的线，再往里填东西 |
| **人天** | 一个人干一天的工作量。整个项目约 15 人天 |
| **Issue** | 一张任务单 |
| **Acceptance Criteria** | 验收条件，写清楚"做到什么样算完成" |
| **Feature Freeze** | 功能冻结，之后不准再加新功能 |
| **单测** | 单独测一个小函数对不对，比如算"单次穿着成本"对不对 |
| **E2E（端到端）** | 从第一步一直点到最后的测试。**我们手工跑，不写代码** |
| **mock** | 假装接口报错，用来测"AI 挂了用户还能不能用" |
| **commit** | 把代码存一个存档点 |

## 五、真正重要的，只有这 5 件事

其他都可以妥协，这 5 件不行：

1. **第 6 周的线必须打通。** 打不通就砍东西（见第六节），别往后拖。
2. **AI 不能直接写数据。** 一定要"AI 建议 → 人确认 → 才存"。
3. **AI 不能说"不知道"以外的谎。** 拿不准就输出"不确定"，别猜材质、别猜品牌。
4. **二维码必须真打印、真扫一次。** 不能只在电脑屏幕上看着像能扫。
5. **每天存一下 AI 提示词。** 这是比赛材料，不是可选项。

## 六、卡住了怎么办

**第 6 周周日，那条线还没通？**

按这个顺序砍，砍到能通为止：

```
先砍 → 其他 5 个状态按钮（只留「穿了」）
再砍 → 标签排版（二维码直接显示在网页上，截图打印）
再砍 → 列表页和详情页（入柜成功就行）
最后留 → 拍照 → AI → 存库 → 二维码 → 手机扫开 → 点一下
```

**AI 识别老是不准？**
先别调。把没把握的字段改成"不预填"，让用户自己填 —— 产品依然成立，而且答辩时可以讲"我们发现 AI 有边界，所以设计了用户确认机制"，这是加分不是减分。

**手机扫不开标签？**
1. 检查二维码是不是印得太小（必须 50×30mm，别为了省纸做小）
2. 检查容错级别是不是 M 或 H
3. 检查网址是不是 HTTPS 开头
4. 换个手机试，排除是不是某台手机的问题

**时间不够了？**
砍功能，**不要砍**：实打印测试、AI 准确率报告、3 人试用。这三样是拿分的，不是花钱的。

## 七、开工第一天，先做这三件

1. **配一个能用手访问的临时地址。** 敲一行 `cloudflared tunnel --url http://localhost:3000`，拿到的那个网址，用手机能打开就行。**没有这个，第 5 天没法测扫码。**
2. **建 GitHub 仓库**，把 `docs/`、`prompts/` 两个空文件夹建好。
3. **打开 `docs/AI-USAGE-LOG.md`，写第一行**：今天用了什么 AI、问了什么。之后每天加一行。
